## Checklist

### Cài đặt và bootstrap
- [ ] Argo CD cài từ `manifests/install.yaml` của tag **`v3.6.1`**, **vendor** vào `bootstrap/argocd/upstream/install.yaml` (ghi sha256 trong comment), không trỏ nhánh `stable` hay `HEAD`. Base từ xa trỏ HEAD có thể "đột ngột đổi nghĩa". Vendor thay vì URL tag vì tag git dời được, repo-server khỏi tải GitHub mỗi lần sinh manifest, và nâng cấp hiện thành diff trong commit (G0-03). [Best Practices – immutability](https://argo-cd.readthedocs.io/en/stable/user-guide/best_practices/), [Installation](https://argo-cd.readthedocs.io/en/stable/operator-manual/installation/)
- [ ] `gitops/bootstrap/argocd/kustomization.yaml` dùng manifest Argo CD làm resource và patch cấu hình (`argocd-cm`, `argocd-rbac-cm`, `argocd-cmd-params-cm`). Docs đề xuất quản lý Argo CD bằng Kustomize overlay. [Declarative Setup – Manage Argo CD Using Argo CD](https://argo-cd.readthedocs.io/en/stable/operator-manual/declarative-setup/#manage-argo-cd-using-argo-cd)
- [ ] Bootstrap đúng hai lệnh tay thay đổi cụm, ghi trong runbook `gitops/bootstrap/README.md`: `kubectl apply --server-side -k bootstrap/argocd`, rồi `kubectl apply -f apps/<env>/projects.yaml -f apps/root-<env>.yaml` (client-side, vì project `default` do Argo CD tự tạo). Giữa hai lệnh có lệnh **chỉ chờ**: `kubectl wait --for=condition=Established` cho CRD (kubectl dò kiểu một lần mỗi lệnh, nên CR không đi chung lệnh với CRD của nó; vì vậy AppProject nằm ở `apps/<env>/`, không ở `bootstrap/`), và `kubectl -n argocd wait --for=condition=Available deployment --all` cùng `rollout status` controller (root tạo lúc repo-server chưa Ready sẽ kẹt `Unknown` tới hết `timeout.reconciliation`, đo được 179 s so với 50 s). Sau đó mọi thay đổi (kể cả nâng Argo CD) đi qua Git. [Cluster Bootstrapping](https://argo-cd.readthedocs.io/en/stable/operator-manual/cluster-bootstrapping/)
- [ ] `Application` tự quản lý Argo CD có sync option `ServerSideApply=true`. Docs ghi đây là **bắt buộc** khi Argo CD quản lý chính nó. [Declarative Setup](https://argo-cd.readthedocs.io/en/stable/operator-manual/declarative-setup/#manage-argo-cd-using-argo-cd)
- [ ] Cứu hộ khi một commit làm hỏng chính Argo CD: revert trong Git rồi chạy lại lệnh 1 **kèm `--force-conflicts`**. Sau khi Argo CD tiếp quản, field thuộc field manager `argocd-controller`; thiếu cờ này kubectl báo conflict và không áp gì (đo ở G0-03).
- [ ] Bảo vệ Argo CD khỏi chính nó: root app và app tự quản lý Argo CD **không** có finalizer `resources-finalizer` (xóa nhầm chỉ làm app con mồ côi, không cascade); root không tự quản lý (file nằm ngoài `apps/<env>/`); Namespace `argocd`, ba CRD `argoproj.io` và `ApplicationSet` service có `argocd.argoproj.io/sync-options: Prune=false` (prune CRD là xóa mọi Application; prune ApplicationSet là xóa mọi service). [Sync Options – No Prune](https://argo-cd.readthedocs.io/en/stable/user-guide/sync-options/#no-prune-resources)
- [ ] Memory request = limit theo ngân sách ADR-0004, kèm `GOMEMLIMIT` ≈ 90% limit cho mọi thành phần Go (controller, repo-server, server, applicationset). Không có nó, Go không biết trần container: G0-03 đo controller 451/512 MiB working set trong khi `heap_alloc` chỉ 131 MiB. [Go GC guide – Memory limit](https://go.dev/doc/gc-guide#Memory_limit)
- [ ] Namespace `argocd` gắn Pod Security `enforce: restricted` và ghim `enforce-version` theo bản Kubernetes. Pod của `install.yaml` v3.6.1 đã đạt `restricted`. [Pod Security Admission](https://kubernetes.io/docs/concepts/security/pod-security-admission/)
- [ ] Nâng Argo CD từng minor một và đọc trang upgrade tương ứng trước khi thay bản vendor (ví dụ 3.5→3.6 đổi tên biến OTel của repo-server, bật Server-Side Diff cho app dùng SSA). [Upgrading 3.5→3.6](https://argo-cd.readthedocs.io/en/stable/operator-manual/upgrading/3.5-3.6/)

### Cấu trúc Application: app-of-apps + ApplicationSet
- [ ] Mỗi môi trường có **một** root `Application` (app-of-apps) trỏ `apps/<env>/`. Thư mục này chứa `AppProject`, `Application` của hạ tầng (Argo CD, Sealed Secrets, Strimzi, CloudNativePG, LGTM, Keycloak, và các thành phần cửa vào cụm của app `platform` ở mục dưới) và một `ApplicationSet` cho service. [Cluster Bootstrapping – App of Apps](https://argo-cd.readthedocs.io/en/stable/operator-manual/cluster-bootstrapping/)
- [ ] Chỉ admin được push vào `apps/` và review trường `project`. Docs gọi app-of-apps là "an admin-only tool". [Cluster Bootstrapping](https://argo-cd.readthedocs.io/en/stable/operator-manual/cluster-bootstrapping/)
- [ ] Service sinh bằng `ApplicationSet` với Git **files** generator quét `envs/<env>/*/values.yaml`; thêm service là thêm file values. Files thay vì directory generator để thư mục tạo dở (chưa có values) không sinh app lỗi; template chỉ dùng tham số `.path.*`, không dùng nội dung values. Tên app có tiền tố `svc-` để không trùng app hạ tầng. Trường `project` **viết cứng**, không template hóa. Template hóa `project` cho phép người ghi vào nguồn generator đưa app vào project lỏng hơn. [ApplicationSet Security](https://argo-cd.readthedocs.io/en/stable/operator-manual/applicationset/Security/)
- [ ] Application service dùng multiple sources: chart `app` từ OCI registry (`ghcr.io/<user>/charts`, sửa 2026-11-15, ADR-0017) + `ref: values` trỏ repo `gitops`, `valueFiles: [$values/envs/<env>/<svc>/values.yaml]`. `$values` chỉ dùng ở đầu đường dẫn; source có `ref` không được có `chart`. [Multiple Sources](https://argo-cd.readthedocs.io/en/stable/user-guide/multiple_sources/)
- [ ] `targetRevision` của chart là version SemVer cụ thể, không dùng range. Chart đổi version phải là một commit trong `gitops`, rollback được. [Best Practices](https://argo-cd.readthedocs.io/en/stable/user-guide/best_practices/)
- [ ] (Sửa 2026-11-15, [ADR-0017](../adr/0017-images-and-charts-on-ghcr.md)) Chart `app` kéo từ GHCR qua HTTPS. Package public thì Argo CD kéo không cần credentials, không cần repo secret; package có public không là **chưa xác minh**, chốt ở ticket G0-17 (không thì bật public một lần cho mỗi package). Bỏ `insecureOCIForceHttp`. Ghi chú cũ, chỉ còn giá trị khi gặp lại registry HTTP: `insecureOCIForceHttp: "true"` không được kèm `insecure: "true"` (skip TLS verify) hay `enableOCI` trên repo `type=helm`, vì Helm v4 bỏ âm thầm `--plain-http` khi có cả hai cờ, và `type=helm` + `enableOCI` + force-HTTP làm kéo chart thất bại. [Upgrading 3.4→3.5](https://argo-cd.readthedocs.io/en/stable/operator-manual/upgrading/3.4-3.5/)
- [ ] Child app có finalizer `resources-finalizer.argocd.argoproj.io` (trừ root và app tự quản lý Argo CD, xem mục Cài đặt); tài nguyên giữ dữ liệu (PVC, CR `Cluster` của CloudNativePG, CR `Kafka`) có annotation `argocd.argoproj.io/sync-options: Delete=false`. Xóa nhầm app không được kéo theo dữ liệu. [Declarative Setup – finalizer](https://argo-cd.readthedocs.io/en/stable/operator-manual/declarative-setup/), [Sync Options – Delete=false](https://argo-cd.readthedocs.io/en/stable/user-guide/sync-options/)

### App `platform`: cửa vào cụm và PKI
- [ ] App `platform` có thêm: CRD Gateway API **v1.6.1 standard** (Application riêng), cert-manager (Helm value `config.gatewayAPI.enabled: true`), trust-manager **v0.26.0** (wave 4) cùng `Bundle` `lab-trust` và `lab-root` (trong app `lab-ca`, G0-07), Envoy Gateway **v1.10.0** (chart `gateway-helm`, `crds.enabled=false` hoặc `source.helm.skipCrds: true` vì CRD đã cài riêng), `GatewayClass envoy`, `EnvoyProxy`, namespace `edge` với Gateway `edge` và route chuyển HTTP sang HTTPS, Sealed Secret `lab-intermediate-ca` và `ClusterIssuer lab-ca`, cùng HTTPRoute của Keycloak, Argo CD, Grafana. Namespace được gắn route mang nhãn `edge.lab.internal/routes: "true"`; namespace cần trust bundle mang nhãn `trust.lab.internal/inject: "true"`; chỉ `platform` gắn hai nhãn này. Chi tiết và giá trị ở [`cluster-entry.md`](cluster-entry.md). [ADR-0013](../adr/0013-gateway-api-envoy-gateway-shared-edge.md), [ADR-0014](../adr/0014-lab-pki-and-dns.md)
- [ ] Thứ tự sync wave trên child `Application`: **CRD Gateway API → cert-manager → trust-manager và Envoy Gateway → Gateway `edge`, `ClusterIssuer lab-ca` → app**. CRD Gateway API phải có trước khi cert-manager khởi động, nếu không thì cert-manager phải restart mới thấy Gateway. Envoy Gateway v1.10 yêu cầu CRD v1.6 có trước. [cert-manager – Gateway](https://cert-manager.io/docs/usage/gateway/), [Envoy Gateway – Install with Helm](https://gateway.envoyproxy.io/docs/install/install-helm/) Wave thực tế ở G0-06: Sealed Secrets 1, CRD Gateway API 2, cert-manager 3, Envoy Gateway 4, `edge` và `lab-ca` 5 (trust-manager G0-07 xếp ở 4). `lab-ca` là app riêng (SealedSecret wave -1 trong app, rồi `ClusterIssuer`), vì `ClusterIssuer` không tạo được cùng lần sync cài CRD của nó và PKI có vòng đời riêng.
- [ ] Application CRD Gateway API và Envoy Gateway có sync option `ServerSideApply=true`, không `CreateNamespace=true` (namespace do `platform` tạo). Docs Envoy Gateway dùng server-side apply để tránh giới hạn annotation 262 144 byte. [Envoy Gateway – Install with Argo CD](https://gateway.envoyproxy.io/docs/install/install-argocd/)
- [ ] Argo CD mở qua `https://argocd.lab.internal` (HTTPRoute gắn vào `edge`): `server.insecure: "true"` trong `argocd-cmd-params-cm` (Envoy terminate TLS), `url: https://argocd.lab.internal` trong `argocd-cm` (redirect URI ổn định cho SSO Keycloak). CLI dùng `--grpc-web` hoặc thêm GRPCRoute. [Argo CD – Ingress configuration (Gateway API)](https://argo-cd.readthedocs.io/en/stable/operator-manual/ingress/) Làm ở G0-06: route nằm trong app `edge`; đổi `argocd-cmd-params-cm` phải `rollout restart deploy argocd-server`; NetworkPolicy của `argocd-server` được patch cho chỉ Envoy vào (chi tiết ở [`cluster-entry.md`](cluster-entry.md#hostname-và-ui-vận-hành)). Đăng nhập CLI: `argocd login argocd.lab.internal --grpc-web`; qua port-forward thì `--plaintext` (cập nhật `bootstrap/README.md`).

### AppProject: giới hạn nguồn và đích
- [ ] Project `default` bị khóa: `sourceRepos: []`, `destinations: []`, `clusterResourceWhitelist: []` **ghi tường minh**, `namespaceResourceBlacklist` `*/*`. Mặc định nó cho mọi repo, mọi cluster, mọi Kind. Argo CD tự tạo `default` với `clusterResourceWhitelist: */*`; apply giữ nguyên field manifest không nhắc tới, nên bỏ trống field là vẫn còn `*/*` (G0-03 bước 6). [Projects – default project](https://argo-cd.readthedocs.io/en/stable/user-guide/projects/)
- [ ] Project `platform` (hạ tầng): được tạo tài nguyên cluster-scoped cần thiết; chỉ admin dùng. Project nào có đích là namespace `argocd` thì tương đương quyền admin. [Declarative Setup – Projects](https://argo-cd.readthedocs.io/en/stable/operator-manual/declarative-setup/#projects)
- [ ] Project `commerce` (service): `sourceRepos` chỉ gồm repo `gitops` và registry chart; `destinations` chỉ namespace của service; `clusterResourceWhitelist: []`; `namespaceResourceBlacklist` gồm `ResourceQuota`, `LimitRange`, `Gateway`, `BackendTLSPolicy` (chỉ `platform` tạo; `GatewayClass` là cluster-scoped nên đã bị chặn), và `Role`, `RoleBinding` (không cấm thì service tự cấp `cluster-admin` trong namespace cho ServiceAccount của mình rồi sửa các Kind trên từ trong pod; chart `app` không tạo RBAC). `NetworkPolicy` không bị cấm vì chart `app` tự render policy cho từng app (ticket [11](../.scratch/architecture-g0-g1/issues/11-service-template.md#answer)). Service chỉ được tạo `HTTPRoute` ([`cluster-entry.md`](cluster-entry.md#gateway-edge-và-sở-hữu)). [Declarative Setup – Projects](https://argo-cd.readthedocs.io/en/stable/operator-manual/declarative-setup/#projects)

### Sync policy
- [ ] App service: `syncPolicy.automated` với `prune: true`, `selfHeal: true`; `allowEmpty` để mặc định `false`. Prune và self-heal mặc định tắt; `allowEmpty: false` chặn lỡ làm rỗng app. [Automated Sync Policy](https://argo-cd.readthedocs.io/en/stable/user-guide/auto_sync/)
- [ ] `syncPolicy.retry` có `limit` hữu hạn (ví dụ 5) và backoff; không đặt `-1`. Automated sync không thử lại cùng commit đã thất bại nếu không có retry. [Automated Sync Policy – retry](https://argo-cd.readthedocs.io/en/stable/user-guide/auto_sync/)
- [ ] Sync options mặc định cho app service: `PruneLast=true`, `FailOnSharedResource=true`; không dùng `Replace=true`; không dùng `CreateNamespace=true` (namespace do project `platform` tạo, kèm quota và NetworkPolicy). [Sync Options](https://argo-cd.readthedocs.io/en/stable/user-guide/sync-options/)
- [ ] Không đưa vào Git trường do controller khác quản lý: không có `spec.replicas` khi bật HPA/KEDA (xem [`helm-chart.md`](helm-chart.md)); khác biệt còn lại khai báo `ignoreDifferences` + `RespectIgnoreDifferences=true`. [Best Practices – leave room for imperativeness](https://argo-cd.readthedocs.io/en/stable/user-guide/best_practices/)

### Sync waves, hooks, health
- [ ] Thứ tự trong một app: wave `-1` cho `SealedSecret`, `ConfigMap`; migration là hook `PreSync` (chi tiết ở [`db-migration.md`](db-migration.md)); workload wave `0`; smoke test là hook `PostSync` (smoke test **Hoãn tới G7**, 2026-11-15, cùng e2e). Wave nhỏ chạy trước; PreSync lỗi thì dừng sync. [Sync Phases and Waves](https://argo-cd.readthedocs.io/en/stable/user-guide/sync-waves/) Argo CD xếp **phase trước, wave sau**: resource thường ở wave `-1` vẫn thuộc phase Sync, tức áp sau mọi hook `PreSync`. Thứ gì Job `PreSync` cần (credential của migrator) phải là hook `PreSync` ở wave nhỏ hơn Job; Argo CD chờ nó `Healthy` rồi mới chạy wave kế. Đã làm ở G0-27 (chart `app` 0.3.0, `sealedSecrets.<tên>.preSync`): event `Unsealed` của SealedSecret hook đứng trước SealedSecret thường 2 s ([bản ghi](../experiments/2026-11-g0-27-hello-presync.md)). Phần `PreSync` và `SealedSecret` đã đạt; mục để chưa tick vì smoke `PostSync` hoãn G7.
- [ ] Biết rằng app con `Degraded` trong một wave làm sync của root **thất bại và retry trên đúng revision cũ** (theo `retry` của root: 5 lần, backoff tới 3 phút). Trong lúc đó commit sửa lỗi đã push không được áp. Đo ở G0-05: app thử `Degraded` ở wave 6 giữ root ở revision cũ thêm vài phút sau khi đã push commit gỡ nó. Khi cần áp ngay: `argocd app terminate-op root-lab` rồi sync lại. G0-13 (2026-11-28) gặp lại khi Grafana CrashLoop: commit nâng limit nằm trong `valuesObject` của Application, tức do **root** áp, nên root bị ghim thì sửa không tới được app con. `argocd app terminate-op root-lab --core` cần context kubeconfig ở namespace `argocd` (không thì lỗi `configmap "argocd-cm" not found`). Vì vậy app thử nghiệm cố ý hỏng không nằm dưới root lâu hơn phép thử.
- [x] Hook (kể cả Helm hook mà Argo CD ánh xạ sang `PreSync`) không nằm trong diff: commit chỉ đổi hook thì app vẫn `Synced`, auto-sync không chạy, hook mới chỉ chạy ở lần sync kế tiếp (G0-05: đổi Job `certgen` phải `argocd app sync` tay để thử). Gặp lại hai lần ở G0-27: commit chỉ bật `migration.enabled`, và `git revert` commit image sau một sync lỗi (trạng thái mong muốn bằng đúng trạng thái đang chạy), đều cho app `Synced` mà không có operation nào. Sync tay bằng `kubectl -n argocd patch application <app> --type merge -p '{"operation":{"sync":{"syncStrategy":{"hook":{}}}}}'` (runbook [migration-presync.md](../runbooks/migration-presync.md)).
- [x] Commit đổi `targetRevision` của chart trong ApplicationSet **và** values của service được áp thành hai lần sync: values vào app ngay, còn `targetRevision` phải chờ app root cập nhật ApplicationSet. Giữa hai lần, chart cũ chạy với values mới (G0-27: 15:27:16 chart 0.2.0 với values mới, 15:28:02 chart 0.3.0). Thay đổi cần cả chart mới lẫn values mới thì nâng chart ở một commit trước.
- [ ] Giá trị `null` trong `helm.valuesObject` bị mất khi lưu Application, nên không dùng được để xóa key mặc định của chart. Dùng `helm.parameters` với `value: "null"` (Helm hiểu `--set key=null` là xóa key). Đã thử ở G0-05 với `certgen.job.ttlSecondsAfterFinished` của Envoy Gateway.
- [x] Mọi hook idempotent. Hook chạy ở **mọi** lần sync, kể cả self-heal. [Sync Phases and Waves](https://argo-cd.readthedocs.io/en/stable/user-guide/sync-waves/)
- [x] Hook Job dùng `hook-delete-policy: BeforeHookCreation` (giữ Job gần nhất để đọc log) và **không** đặt `ttlSecondsAfterFinished`. Kubernetes có thể xóa Job trước khi Argo CD đọc kết quả. Chậm nhất khoảng 7 phút. Chưa rút ngắn ở G0 (webhook cần đường từ internet vào cụm; giảm thời hạn cache tăng số lần gọi GitHub), xét lại ở G7. Argo CD chỉ áp revision mới nhất nó thấy ở mỗi lần poll: ba commit sát nhau chỉ cho một lần sync.

- **Argo CD sau Gateway `edge` dùng edge termination** (`server.insecure`): traffic giữa Envoy và `argocd-server` không mã hóa trong mạng pod; NetworkPolicy chỉ cho Envoy vào. - **Bản sao lưu khóa sealing ở dạng rõ, chỉ một bản, trên Mac của chủ repo** (`~/.commerce-hub/sealing-keys/`, thư mục `700`, file `600`, loại khỏi Time Machine bằng `tmutil addexclusion`, FileVault bật), thay vì password manager hoặc ổ mã hóa như checklist mục Secret. Rủi ro chấp nhận: (1) mất hoặc cài lại Mac rồi sau đó mất cụm thì không giải mã được SealedSecret nào, phải sinh lại và seal lại mọi secret; (2) tiến trình nào chạy dưới tài khoản chủ repo cũng đọc được private key, mà ciphertext nằm trong repo public, nên lộ file là lộ mọi secret, kể cả bản cũ trong lịch sử Git. Đường nâng lên đúng chuẩn đã thử với dữ liệu giả: ảnh đĩa `hdiutil create -encryption AES-256 -format UDZO` (chỉ đọc), mật khẩu trong Passwords, ảnh đĩa đặt ngoài Mac (iCloud Drive hoặc USB); các bước ở [`runbooks/sealing-key.md`](../runbooks/sealing-key.md#sao-lưu-khóa). | Thứ tự cửa vào | Cụm trắng → bootstrap; xem thứ tự `Synced/Healthy` của các app `platform` | CRD Gateway API → cert-manager → trust-manager, Envoy Gateway → Gateway `edge` `Programmed`, `ClusterIssuer lab-ca` `Ready` → app; cert-manager không cần restart tay |
| Argo CD qua `edge` | Mở `https://argocd.lab.internal` từ Mac, đăng nhập (SSO hoãn G7; tới lúc đó đăng nhập `admin`) | Không cảnh báo TLS; khi có SSO thì quay về đúng `url` |
| Chart từ GHCR (sửa 2026-11-15, ADR-0017) | App multi-source kéo chart `app` từ `oci://ghcr.io/<user>/charts/app`, không repo secret | `Synced`; không có lỗi xác thực khi kéo chart |
