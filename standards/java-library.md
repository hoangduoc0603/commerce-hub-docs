# Chuẩn: Thư viện Java dùng chung (Gradle convention plugin, publish Maven, luật kiến trúc)

> **Phạm vi từ 2026-11-15** ([ADR-0018](../adr/0018-self-contained-services-no-shared-library-yet.md)): dự án thôi dùng `libs/service-kit` và chưa có thư viện dùng chung. Repo `commerce-hub-service-kit` đã archive, reusable workflow `java-library.yml` đã xóa khỏi `platform`.
>
> - **Còn áp dụng** cho artifact Maven của `contracts` (ticket 19, 20): mục "Version, publish, bất biến" (version từ tag, ruleset khóa tag `v*`, publish chỉ từ commit trên nhánh mặc định, 409 khi publish lại), cùng các dòng tương ứng của bảng "Bằng chứng cần có". Workflow publish của `contracts` viết lại ở ticket 19; mã cũ của `java-library.yml` nằm trong history của `platform` (commit `f836c28`).
> - **Lịch sử, không áp dụng:** cấu trúc repo nhiều module, convention plugin, composite build, luật kiến trúc (`test-support`), Testcontainers và bảng tag image, phía consumer, CI của lib. Build của service theo [`spring-service.md`](spring-service.md). Giữ nguyên văn để dùng lại nếu G1 xét lại việc tách thư viện.

Artifact **mức đầy đủ** (CLAUDE.md, mục Chuẩn production): code dùng chung của mọi service backend. Phần workflow CI của lib theo [`ci-cd.md`](ci-cd.md) (mức tối thiểu).

- Phiên bản áp dụng: Gradle 9.9.1 (Groovy DSL, `groovy-gradle-plugin`, `java-gradle-plugin`, `maven-publish`), Java 25 (Temurin), Spring Boot 4.1.2 (quản lý JUnit 6.0.3, Testcontainers 2.0.5), ArchUnit 1.5.1 (`archunit-junit6`), PostgreSQL 18.7 (image `postgres:18.7`), `gradle/actions/setup-gradle` v6.4.1 (`8da46b539cd8fe6ab27ca75128919a18d757604c`), GitHub Packages (Maven registry).

## Checklist

### Cấu trúc repo
- [ ] Một repo, nhiều module, **chung một version**; mỗi bản gắn với một minor Spring Boot (ticket 11 của map, Q12, Q15).
- [ ] Tọa độ: groupId `io.github.hoangduoc0603.commercehub.kit`, artifactId là tên module (`gradle-plugin`, `test-support`, sau này `workspace-access`, `web`, `ids`); package Java `io.github.hoangduoc0603.commercehub.kit.<module>`. groupId cộng tên module trùng package, nên đọc tọa độ là biết code ở đâu. Đây là bản cụ thể hóa của Q16 (ticket 11): groupId gốc `io.github.<user>.commercehub` cộng `.kit` cho lib, `.contracts` cho `contracts`.
- [ ] `group` đặt cho **mọi** project (qua `gradle.properties` ở gốc). Không đặt thì group là `undefined` và composite build không thay được phụ thuộc theo `group:name`. [Composite builds](https://docs.gradle.org/9.9.1/userguide/composite_builds.html)
- [ ] Phiên bản phụ thuộc nằm trong `gradle/libs.versions.toml`. Thư viện Spring Boot đã quản lý (JUnit, Testcontainers, Spring) lấy version từ BOM `spring-boot-dependencies`, không ghim lại; thư viện Boot không quản lý (ArchUnit) thì ghim trong catalog. [Spring Boot – Managing dependencies](https://docs.spring.io/spring-boot/gradle-plugin/managing-dependencies.html), [Dependency versions](https://docs.spring.io/spring-boot/appendix/dependency-versions/coordinates.html)
- [ ] Không dùng `allprojects {}`/`subprojects {}` để chia cấu hình giữa module; dùng convention plugin nội bộ (included build `build-logic`) nếu cần. Hai khối đó tạo coupling lúc cấu hình. [Sharing build logic](https://docs.gradle.org/9.9.1/userguide/sharing_build_logic_between_subprojects.html)
- [ ] Bật configuration cache trong `gradle.properties` (`org.gradle.configuration-cache=true`). Gradle 9 mặc định tắt nhưng coi đây là chế độ nên dùng. [Enabling the Configuration Cache](https://docs.gradle.org/9.9.1/userguide/configuration_cache_enabling.html), [Gradle 9.0 release notes](https://docs.gradle.org/9.0.0/release-notes.html)
- [ ] Gradle Wrapper commit vào repo, có `distributionSha256Sum` lấy từ [gradle.org/release-checksums](https://gradle.org/release-checksums/) (nguồn độc lập với file tải về). `gradle wrapper` mặc định không ghi checksum; có checksum thì bản tải về bị sửa sẽ làm build dừng. [Gradle Wrapper – checksum](https://docs.gradle.org/9.9.1/userguide/gradle_wrapper.html), [Securing the build tool](https://docs.gradle.org/9.9.1/userguide/securing_build_tool.html)
- [ ] Repository khai một chỗ trong `settings.gradle` (`dependencyResolutionManagement`) với `RepositoriesMode.FAIL_ON_PROJECT_REPOS`: module nào tự khai `repositories {}` thì build lỗi. Một chỗ duy nhất quyết định code tải từ đâu. [Centralizing repositories](https://docs.gradle.org/9.9.1/userguide/centralizing_repositories.html)
- [ ] Java toolchain 25: `java { toolchain { languageVersion = JavaLanguageVersion.of(25) } }`. Gradle 9.1+ hỗ trợ Java 25 cả cho toolchain lẫn cho daemon. [Toolchains](https://docs.gradle.org/9.9.1/userguide/toolchains.html), [Compatibility](https://docs.gradle.org/9.9.1/userguide/compatibility.html)

### Convention plugin (precompiled script plugin)
- [ ] Module `gradle-plugin` áp `groovy-gradle-plugin`; script ở `src/main/groovy/commercehub.spring-service.gradle`, id plugin lấy từ tên file. Groovy precompiled script không có package, nên namespace nằm trong tên file. `groovy-gradle-plugin` tự áp `java-gradle-plugin` và đăng ký script vào `gradlePlugin.plugins` (đã đọc trong mã nguồn nhánh `master`, chưa đối chiếu tag 9.9.1). [Precompiled script plugins](https://docs.gradle.org/9.9.1/userguide/implementing_gradle_plugins_precompiled.html)
- [ ] Plugin bên ngoài (Spring Boot) khai báo là `implementation` trong `gradle-plugin/build.gradle` (version lấy từ catalog của repo kit), rồi trong script chỉ ghi `id 'org.springframework.boot'` không version. Khối `plugins {}` của precompiled script không nhận `version` và không đọc được version catalog. [Precompiled script plugins](https://docs.gradle.org/9.9.1/userguide/implementing_gradle_plugins_precompiled.html), [Version catalogs](https://docs.gradle.org/9.9.1/userguide/version_catalogs.html)
- [ ] Plugin ghim: toolchain Java 25; Spring Boot 4.1.x (qua phụ thuộc ở mục trên); BOM của Boot bằng `platform(SpringBootPlugin.BOM_COORDINATES)` cho `implementation` và `annotationProcessor` (cấu hình này không kế thừa `implementation`); `test-support` vào `testImplementation`; `junit-platform-launcher` vào `testRuntimeOnly` và `useJUnitPlatform()` cho mọi task `Test` (`tasks.withType(Test).configureEach`). Service chỉ còn phần riêng (story 58).
- [ ] Module `gradle-plugin` dùng toolchain 25, nên Gradle của service phải chạy trên JDK 25. Plugin của Spring Boot nhắm Java 17 để chạy được trên mọi JDK, nhưng mọi build của dự án đã chạy JDK 25 (Mac, CI `setup-java` 25), nên không hạ bytecode (G0-18 bước 5, Q3).
- [ ] Plugin thêm `test-support` **đúng version của chính plugin**. Cách làm: task `WriteProperties` (có sẵn trong Gradle) ghi `group` và `version` của project vào `commercehub-kit.properties`, `processResources` đặt file vào jar plugin dưới thư mục theo package của module, script đọc bằng `getClass().getResourceAsStream(...)`; thiếu file hay thiếu khóa `group`/`version` thì script ném `GradleException` nêu tên file và task cần kiểm, không để lỗi thành `NullPointerException` hay phụ thuộc `null:test-support:null` (review G0-18). `WriteProperties` không ghi dòng ngày giờ nên jar build lại giống hệt; giá trị đọc thành chuỗi lúc cấu hình để tương thích configuration cache. Docs Gradle không có hướng dẫn riêng cho việc này (mẫu cộng đồng); đã chạy được với configuration cache ở G0-18 bước 6. Đã loại: đọc `Implementation-Version` trong manifest (script không có package để gọi `getPackage()`); sinh class Java chứa hằng số (thêm source set sinh code). Trong composite build, version bị bỏ qua nên không ảnh hưởng. [WriteProperties](https://docs.gradle.org/9.9.1/dsl/org.gradle.api.tasks.WriteProperties.html)
- [ ] TestKit tải `test-support` như service thật: `test-support` publish vào repository dạng thư mục `build/testkit-repo` (publication cơ bản của `maven-publish`), task `test` của `gradle-plugin` `dependsOn` task publish đó, và service tạm khai thư mục này trong `exclusiveContent`. Input của task `test` là thư mục đó trừ `maven-metadata*`, vì Gradle ghi lại `lastUpdated` ở mỗi lần publish, giữ file này thì TestKit chạy lại mọi lần. Đã loại: `includeBuild` thư mục kit từ project của TestKit (build lồng tranh khóa `.gradle` của kit, mỗi test biên dịch lại `test-support`). [Filtering repository content](https://docs.gradle.org/9.9.1/userguide/filtering_repository_content.html), [Incremental build](https://docs.gradle.org/9.9.1/userguide/incremental_build.html)
- [ ] Plugin **không khai repository**. Gradle Best Practices: repository khai trong `settings.gradle`, `FAIL_ON_PROJECT_REPOS`, `exclusiveContent` cho repository riêng. Plugin mà khai repository thì service bật `FAIL_ON_PROJECT_REPOS` không áp được plugin (đã thử: "repository 'MavenRepo' was added by plugin 'commercehub.spring-service'"). Repository nằm trong `settings.gradle` của service (mục "Phía consumer"). Đã loại: plugin khai repository và service để `PREFER_PROJECT` (trái Best Practices, mất cơ chế chặn repository lạ); settings plugin của kit (service vẫn phải khai `pluginManagement` để tìm chính nó, và version không nằm trong catalog). G0-18 bước 5, Q1. [Best Practices for Dependencies](https://docs.gradle.org/9.9.1/userguide/best_practices_dependencies.html), [Centralizing repositories](https://docs.gradle.org/9.9.1/userguide/centralizing_repositories.html)
- [ ] Repository GitHub Packages (trong `settings.gradle` của service) khai báo `credentials(PasswordCredentials)` với `name = 'githubPackages'`: Gradle tìm property `githubPackagesUsername`/`githubPackagesPassword` (trên Mac ở `~/.gradle/gradle.properties`, trên CI qua `ORG_GRADLE_PROJECT_githubPackagesUsername`/`...Password`). Đây cũng là cách docs khuyên để tương thích configuration cache. [Repository protocols – credentials](https://docs.gradle.org/9.9.1/userguide/supported_repository_protocols.html), [Build environment](https://docs.gradle.org/9.9.1/userguide/build_environment.html), [Configuration cache requirements](https://docs.gradle.org/9.9.1/userguide/configuration_cache_requirements.html)
- [ ] Không có Gradle task tự chế để chạy luật kiến trúc: plugin chỉ đưa `test-support` vào classpath test, service viết một class test `@AnalyzeClasses` (quyết định Q4 của ticket G0-18).
- [ ] Test plugin bằng TestKit trong source set `test` mặc định: script precompiled không có unit test, và `java-gradle-plugin` tự thêm `gradleTestKit()` cùng classpath plugin-under-test cho source set này (`withPluginClasspath()`). Tách `functionalTest` khi có unit test thật (G0-18 bước 5, Q2). Mỗi test dựng một project tạm có `settings.gradle` bật `FAIL_ON_PROJECT_REPOS` như service thật, chạy với `--configuration-cache`, rồi `build()` (mong xanh) hoặc `buildAndFail()` (mong đỏ). [Testing Gradle plugins](https://docs.gradle.org/9.9.1/userguide/testing_gradle_plugins.html), [TestKit](https://docs.gradle.org/9.9.1/userguide/test_kit.html)

### Version, publish, bất biến
- [ ] SemVer 2.0.0. Version **lấy từ tag**: `gradle.properties` gốc có `version=0.0.0-local`, CI truyền `-Pversion=${GITHUB_REF_NAME#v}`; tham số `-P` trên dòng lệnh đè giá trị trong `gradle.properties`, nên không cần code đọc property (G0-18 bước 7, Q2; ban đầu định dùng `-PreleaseVersion`). Ném lỗi thay vì `onlyIf`: `onlyIf` bỏ qua task trong im lặng, CI xanh mà không publish gì. [SemVer 2.0.0](https://semver.org/spec/v2.0.0.html), [Build environment – thứ tự ưu tiên](https://docs.gradle.org/9.9.1/userguide/build_environment.html)

Không cần bước kiểm "version đã tồn tại" trong workflow. Version public đã xóa có thể bị dùng lại (suy luận từ điều kiện khôi phục), nên không xóa version đã phát hành; lỗi thì ra bản vá. [Deleting and restoring a package](https://docs.github.com/en/packages/learn-github-packages/deleting-and-restoring-a-package), [SemVer – mục 3](https://semver.org/spec/v2.0.0.html)

- [ ] Consumer thay lib bằng mã nguồn local qua composite build, không qua SNAPSHOT (story 65). `includeBuild` trong `pluginManagement {}` thay **plugin**; `includeBuild` ở cấp gốc thay **phụ thuộc** theo `group:name`, bỏ qua version. [Composite builds](https://docs.gradle.org/9.9.1/userguide/composite_builds.html)
- [ ] `--include-build ../../libs/service-kit` trên dòng lệnh thay được cả plugin áp bằng `plugins { alias(...) }` lẫn `test-support`, dù catalog của consumer ghi `0.1.0` còn kit đang ở `0.0.0-local` (đã thử ở G0-18 bước 8, Gradle 9.9.1; docs ghi cách này "có thể không ổn định" với plugin). `./gradlew dependencies` cho `test-support:0.0.0-local -> project ':service-kit:test-support'`, không có SNAPSHOT. Không cần `includeBuild` cố định trong `settings.gradle` (CI và máy không có repo kit bên cạnh sẽ lỗi). [Composite builds](https://docs.gradle.org/9.9.1/userguide/composite_builds.html)
- [ ] Composite build vẫn cần credentials của `githubPackages`: Gradle kiểm credentials của mọi repository có khai credentials trước khi resolve, kể cả khi group đã được thay bằng included build và không request nào tới GitHub (đã thử: thiếu property thì dừng với "The following Gradle properties are missing for 'githubPackages' credentials", ở cả `pluginManagement` lẫn `dependencyResolutionManagement`). Developer đặt PAT trong `~/.gradle/gradle.properties` từ đầu; không thêm logic điều kiện vào `settings.gradle` của service. [Repository credentials](https://docs.gradle.org/9.9.1/userguide/supported_repository_protocols.html)

Docs ArchUnit gọi đây là cách dùng lại thư viện luật giữa các project. [ArchUnit user guide – JUnit Support, Grouping Rules](https://www.archunit.org/userguide/html/000_Index.html)
- [ ] Luật dùng mẫu package tương đối (`..domain..`, `..application..`, `..adapter..`), không chứa tên package gốc của service.
- [ ] `onionArchitecture()` (ArchUnit gọi là Hexagonal / Ports and Adapters): `domainModels("..domain..")`, `applicationServices("..application..")`, **một** adapter chung `adapter("adapter", "..adapter..")`. Luật này chặn domain phụ thuộc application hay adapter, application phụ thuộc adapter (story 59). Không liệt kê từng adapter: luật onion dùng `consideringAllDependencies()`, nên adapter nằm ngoài danh sách (ví dụ `adapter.out.shopee` của `channel-connector`) thành class ngoài lớp và gọi vào `application` là vi phạm; mỗi adapter mới sẽ phải ra bản kit mới (G0-18 bước 3, Q1). [ArchUnit user guide – Onion Architecture](https://www.archunit.org/userguide/html/000_Index.html), [Architectures.java v1.5.1](https://github.com/TNG/ArchUnit/blob/v1.5.1/archunit/src/main/java/com/tngtech/archunit/library/Architectures.java)
- [ ] Adapter không gọi nhau: `slices().matching("..adapter.(*).(*)..").should().notDependOnEachOther()`. Mỗi `adapter.<in|out>.<tên>` là một slice, nên luật áp cho mọi tên adapter. Luật onion với adapter chung không bắt được `adapter.in.web` gọi `adapter.out.persistence` (đã thử). [ArchUnit user guide – Slices](https://www.archunit.org/userguide/html/000_Index.html)
- [ ] Class nằm ngoài ba lớp (package gốc, `config`) không được gọi vào lớp nào: đây là hệ quả của `consideringAllDependencies()` và được giữ chặt. Class `main` có `@SpringBootApplication` không gọi vào lớp nào; use case đánh `@Service` trong `application` (luật chỉ cấm Spring ở `domain`); cấu hình riêng của adapter đặt trong adapter đó. Khi có case thật cần composition root, thêm `ignoreDependency` cho `..config..` ở một bản minor của kit (G0-18 bước 3, Q2).
- [ ] Thêm luật riêng `noClasses().that().resideInAPackage("..domain..").should().dependOnClassesThat().resideInAnyPackage("org.springframework..")`. `onionArchitecture()` chỉ kiểm chiều *ai được gọi vào lớp nào*, không cấm domain phụ thuộc thư viện bên ngoài (đọc trong `Architectures.java` v1.5.1). `jakarta.persistence..` được phép trong domain cho service JPA (ticket 11, Q11). [Architectures.java v1.5.1](https://github.com/TNG/ArchUnit/blob/v1.5.1/archunit/src/main/java/com/tngtech/archunit/library/Architectures.java)
- [ ] Mọi luật cho phép rỗng: `withOptionalLayers(true)` cho luật onion, `allowEmptyShould(true)` cho hai luật còn lại. Template `hello` chưa có class `domain` hay adapter nào; mặc định `archRule.failOnEmptyShould=true` sẽ đánh trượt nó. Rủi ro mà mặc định đó chặn (gõ sai mẫu package làm luật không kiểm gì) do test tự kiểm ở mục dưới bắt: đổi `..domain..` thành `..domian..` thì test đỏ (G0-18 bước 3, Q3). [ArchUnit user guide](https://www.archunit.org/userguide/html/000_Index.html), [ArchRule javadoc](https://javadoc.io/doc/com.tngtech.archunit/archunit/latest/com/tngtech/archunit/lang/ArchRule.html)
- [ ] Luật tự kiểm: test của `test-support` import package fixture bằng `new ClassFileImporter().importPackages(...)`; fixture đúng layout và fixture rỗng thì mọi luật không ném; mỗi luật có ít nhất một fixture vi phạm làm nó ném `AssertionError`, và test kiểm thông báo lỗi có tên class vi phạm (để luật đỏ đúng lý do). Fixture nằm trong `src/test` nên không vào jar publish. Không có test này thì luật sai mẫu package sẽ xanh mãi. [ArchUnit user guide](https://www.archunit.org/userguide/html/000_Index.html)

### Phía consumer (service)
- [ ] `settings.gradle` khai `pluginManagement { repositories { gradlePluginPortal(); exclusiveContent { forRepository { maven { name = 'githubPackages'; url = 'https://maven.pkg.github.com/hoangduoc0603/commerce-hub-service-kit'; credentials(PasswordCredentials) } }; filter { includeGroup 'io.github.hoangduoc0603.commercehub.kit'; includeGroup 'commercehub.spring-service' } } } }`. Plugin được tìm trước khi script build chạy, nên repository của plugin phải nằm ở settings. Filter có **hai** group: marker của plugin có group là id plugin (`commercehub.spring-service`), không phải group của kit; thiếu group này Gradle đi tìm marker ở Plugin Portal. Mẫu đầy đủ: `services/kit-try/settings.gradle` của G0-18 bước 8 (template `hello` chép lại). [Using plugins – pluginManagement](https://docs.gradle.org/9.9.1/userguide/plugins_intermediate.html)
- [ ] `settings.gradle` khai thêm `dependencyResolutionManagement` cho phụ thuộc: `repositoriesMode = RepositoriesMode.FAIL_ON_PROJECT_REPOS`, `mavenCentral()`, và GitHub Packages bọc trong `exclusiveContent { forRepository { ... } filter { includeGroup 'io.github.hoangduoc0603.commercehub.kit' } }`. `exclusiveContent` làm group của kit chỉ được tìm ở GitHub Packages và GitHub Packages chỉ được hỏi cho group đó: token không đi kèm mọi request, và không ai chèn được artifact cùng tọa độ lên Central. Convention plugin không khai repository (mục "Convention plugin"). Template `hello` (ticket 23) và project thử `kit-try` mang sẵn file này. [Best Practices for Dependencies](https://docs.gradle.org/9.9.1/userguide/best_practices_dependencies.html), [Filtering repository content](https://docs.gradle.org/9.9.1/userguide/filtering_repository_content.html)

[Configuring access to private registries for Dependabot](https://docs.github.com/en/code-security/how-tos/secure-your-supply-chain/manage-your-dependency-security/configuring-access-to-private-registries-for-dependabot), [Automatic Dependabot access to GitHub registries](https://docs.github.com/en/code-security/concepts/supply-chain-security/automatic-dependabot-access-to-github-registries)

### CI của lib (mức tối thiểu, chi tiết ở [`ci-cd.md`](ci-cd.md))
- [ ] Workflow mỏng trong repo lib gọi `platform/.github/workflows/java-library.yml` ghim SHA; job `check` chạy cho push, PR và tag; job `publish` chỉ chạy khi `github.ref` là `refs/tags/v*`, sau `check` xanh.

Bước đầu của job kiểm commit của tag đã vào nhánh mặc định bằng `gh api repos/<repo>/compare/<nhánh mặc định>...<sha> --jq .status`: `identical` hoặc `behind` thì đi tiếp, `ahead`/`diverged` thì dừng. Chạy sau `check` thì chỉ `check` ghi cache, và không gửi graph của build đỏ.
- [ ] `setup-gradle` v6 ghim SHA. Mặc định của nó chỉ ghi cache trên nhánh mặc định (`cache-read-only` là `true` khi `ref_name` khác nhánh mặc định, gồm cả tag), và kiểm `gradle-wrapper.jar` (`validate-wrappers: true`).
